N-gram Gap 机制指南

本文档解释 n-gram gap 实验中的核心概念：什么是 table、gate、shell、optimizer grouping，它们如何组合产生 train/val gap，以及关键实验数据。目标读者是刚接手项目的研究者。

1.1 什么是 n-gram table

n-gram table 就是一张巨大的查表（lookup table），和 token embedding 没有本质区别。区别在于：token embedding 用 token id 做 key，n-gram table 用几个连续 token 组成的 context 做 key。

table 的规模

table 类型context行数每行维度hash 方式
unigram单个 token32,768768直接用 token id
bigram前一个 + 当前 token2,097,152 (32K × 64)64 × 2 = 128乘法 XOR hash
trigram前两个 + 当前 token2,097,15264 × 2 = 128乘法 XOR hash
fourgram前三个 + 当前 token2,097,15264 × 2 = 128乘法 XOR hash

bigram/trigram/fourgram 的行数都是 vocab_size × 64 = 32768 × 64 = 2,097,152。hash 把 n 个 token 映射到这个范围内的一个整数。每层用不同的 hash prime，使不同层的同一 context 映射到不同行。

为什么不用直接查表？ 因为 bigram 的可能组合有 32768² ≈ 10 亿种，trigram 有 32768³ ≈ 3.5 万亿种。直接建表不现实。hash 到 2M 行会产生 collision（不同 context 映射到同一行），但 collision 率很低（batch 内 bigram ~20%，trigram ~8%），而且每层用不同 prime + K=2 双 hash 进一步降低有效 collision。

1.2 Hash 机制详解

hash 的作用是把 n 个 token id 压缩成一个 row 号。具体实现是乘法 + XOR + 取模，全部在 GPU 上以 tensor 整数运算完成。

train.py:1536-1546 — hash 计算
# 输入: prev_idx, prev2_idx 是 shifted token id tensor [batch, seq_len] # idx 是当前 token id tensor [batch, seq_len] # Bigram: 两个 token → 一个 row row = ((prev_idx * p1) ^ (idx * p2)) % 2_097_152 # Trigram: 三个 token → 一个 row row = ((prev2_idx * lp[0]) ^ (prev_idx * lp[1]) ^ (idx * lp[2])) % 2_097_152

每层使用不同的 prime 组（来自 MurmurHash/FNV/golden-ratio 家族），保证不同层的同一 context 映射到完全不同的行。K=2 multi-hash 是指每个 n-gram 查两次独立 hash，各取半个维度（64 维），拼成完整的 128 维。

1.3 Gate 机制：table 如何注入到模型

n-gram table 查出的 value 不会直接加到模型输出上——它经过一个 input-dependent gate 控制注入强度。gate 本身是一个小 linear layer + sigmoid。

train.py:1721-1728 — gate 注入
def _add_value_residual(self, branch, v_heads, residual, gate, x, channel_start, heads): # residual = table 查出的 value [B, T, heads, head_dim] residual = residual.view(x.size(0), x.size(1), heads, self.head_dim) # gate: 从 hidden state 取前 32 维 → linear → sigmoid → ×2 gate_input = x[..., channel_start : channel_start + self.ve_gate_channels] value_gate = 2 * torch.sigmoid(gate(gate_input)) # 范围 [0, 2] # 逐位置乘 gate gated = value_gate.unsqueeze(-1) * residual # 加到 attention value 上 return v_heads + gated

gate 初始化为全 0 权重，所以 2×sigmoid(0) = 1.0——训练初期 gate 全开（中性），之后模型自己学习该在什么时候、什么位置放大或抑制 n-gram value 的注入。

gate 是 gap 的关键放大器。实验数据显示：epoch1 期间 trigram gate_rms 只有 0.088（几乎不工作），但进入 epoch2 中段后 gate_rms 上升到 0.29——gate 被训练起来后，table 中积累的历史内容才被"放大"为可见的 train loss 下降。

1.4 Shell 是什么：nanoGPT vs current shell

项目中有两类模型架构，称为 "shell"（外壳）。它们的区别在于 transformer block 的内部结构。

nanoGPT shell

经典 nanoGPT 架构。标准 LayerNorm、标准 attention、标准 MLP。

# NanoGPTBlock x = LayerNorm(x) x = x + SelfAttention(x) x = LayerNorm(x) x = x + MLP(x)

即使加 n-gram table + RMSProp + 高 LR，也不产生 gap。

current shell (GPT)

从 current/GPT 架构移植的 block。包含 x0 residual、resid_lambda、split QKV 等额外结构。

# Block (current shell) x = resid_lambda*x + x0_lambda*x0_gate*x0 x = x + SelfAttention_splitQKV(x) x = x + MLP(x) # attention 内部: V += ngram_gate × table_value

n-gram table 注入到 attention value stream 的方式和 nanoGPT shell 不同。在 current shell 下，gap 出现。

关键区别不在 table 本身（两者都可以有相同的 n-gram table），而在于 reader 的传输路径：current shell 的 attention split QKV + 残差路径使 n-gram value 在后层 residual 中被更有效地放大。这是为什么 nanoGPT shell 即使加上所有组件仍然无 gap，而切到 current shell 后 gap 出现。

"current-style n-gram injection" 指的是 n-gram value 被注入到 attention value stream 的具体坐标和方式。nanoGPT-style injection 和 current-style injection 的数学结构不同（注入位置、gate 通道分配、与 attention 的交互方式），这决定了 reader Jacobian Ji,a 的大小。

关键差异：current-style grouping 给 n-gram table 的 LR 是 0.6，而 nanoGPT-style 只有 0.004——差 150 倍。这个 LR 差异是 gap 出现的必要条件：高 LR 使 table 在 epoch1 内快速积累 train-specific content，到 epoch2 时形成足够强的 history state。

RMSProp 对比 AdamW：为什么对 sparse table 更合适

AdamW（有 first moment）
m = β₁·m + (1-β₁)·grad # momentum v = β₂·v + (1-β₂)·grad² update = lr · m / (√v + ε) # β₁ = 0.8 → 半衰期 ~3 步 # sparse row 隔几十步才被访问 # → m 已衰减到 ~0，等于每次"重启"
RMSProp（无 first moment）
v = β₂·v + (1-β₂)·grad² update = lr · grad / (√v + ε) # β₂ = 0.999 → 半衰期 ~693 步 # ≈ 2 个 epoch 的长度 # → v 能跨 epoch 持久化 # → 写入方向 = 当前梯度，不被稀释

epoch1-2: table 积累 train-specific content

epoch2→3 边界: gate 通道建立

train 阶梯下降 gap

val loss 翘起 gap

9. 频次分解分析

把 loss 按 n-gram context 的训练频次分解，是定位 gap 来源的核心观测量。

频次定义（统一口径）

每个 n-gram context 的频次 = 它在单个 train epoch 内出现的精确次数，由训练前一次性离线扫描的 精确频率索引（GlobalNgramFrequencyIndex）给出，整个训练过程不变。 频次定义仅在 train 上；val 的 token 按"其 context 在 train 中的频次"归类到同一套桶， 因此 val 有 novel 桶（context 在 train 中从未出现），而 train 按定义没有 novel 桶。

桶的边界（精确频次，上下界闭区间）：novel(0) / 1 / 2 / 3 / 4 / 5 / 6-10 / 11-20 / 21-50 / 51-100 / 101-200 / 201-500 / 501-1k / 1k-5k / 5k+。 低频段被细分为单值桶（1/2/3/4/5），便于直接观察最低频 context 的过拟合。

机制解读：频次结构如何决定 gap

训练集的 context 频次呈典型幂律分布：train 侧大部分 token 来自少数高频 context， 但 val 侧有大量 context（尤其 trigram，~30%）在 train 中从未出现（novel）。gap 的成因正是这种分布与多 epoch 重复训练的交互：

  1. novel / 低频 context：模型在 train 中见过几次（低频）或没见过（novel）， 到 epoch3 配合 gate 通道建立，模型把这些 context 的特定后续 token memorize 下来（train loss 坍塌）， 但 val 中即使遇到相同 context，后续 token 也不同，模型"过度自信"反而出错（val loss 翘起）。trigram 的 ~30% val novel 是其 gap 尤为显著的结构性原因。
  2. 高频 context：多为 QA pattern（? Answer: 等），后续 token 天然可预测， train 和 val 的 loss 都相对低且接近，对 gap 贡献最小。
  3. 启示：用 BPE 把高频 token 组合 over-encode 成单个 token、避免对低频 context 建 hash 表， 可以从源头减少低频过拟合——这是后续干预实验的方向（见 agent-experiment-log.html）。
关于 unigram：本 run（baseline_current）的 n-gram value tables 只启用 bigram 与 trigram （ENABLE_UNIGRAM_VE=0），unigram 不参与训练，故无 unigram 频次分解。 如需 unigram 视角，需要一次 ENABLE_UNIGRAM_VE=1 且把 unigram 纳入频次分解的新 run； 服务器环境已就绪（见 实验日志），可在需要时补跑。

10. 扩展实验：干预验证（gap 是否能被消除）

§9 的频次分解定位了 gap 的来源（低中频 n-gram context 过拟合）。本章用两个干预实验直接验证： 若假设成立，干预应能消除/减弱 gap。

实验设置

两个干预都在 20260725e_nano_rmsprop_fixv3 同款设置上跑（table RMSProp, nanogpt_original shell, vocab=8192, n_layer=8, seed42, 1000 step, 单 shard tr1）， 并各加一个 current-shell 版本（同 rmsprop，对照 current-shell baseline baseline_current，即 §2/§7.9/§9 用的同款 setting）。 共 4 个干预 run，各自对照同 shell 的 baseline。所有 run 都到 step 1000、含 3 个 epoch（边界 step 337/686）。
注：§9 的频次分解现已统一到 baseline_current（current shell，gap 量级更大、现象更典型）；本章干预在两个 shell 上都验证，nanogpt_original 用 B.1，current-shell 用 baseline_current 同款配置。

10.1 实验 4：per-epoch hash 错位

假设

n-gram table 的 gap 根因是"同一 context 跨 epoch 重复查到同一行，table 在该行累积 train-specific pattern"。 若每个 epoch 用 epoch 号做 seed 重生成全部 hash primes，使同一 context 跨 epoch 落到完全不同的 row， 则 table 无法跨 epoch 稳定累积 → gap 预期显著降低。

实现：新增 env NGRAM_HASH_RESEED_PER_EPOCH=1；epoch 1 保留 canonical primes（与 baseline 一致）， epoch≥2 边界调用 _reseed_ngram_hash_primes(model, epoch_seed) 用 epoch 号重生成 bigram/trigram/fourgram 全部 primes。 reseed 只改 hash 映射、不改 table 行内容——正好实现"新 epoch 同一 context 查到另一行（未被该 context 训练污染）"。

10.2 实验 5：低频 context 强制 gate=0

假设

§9 显示低中频 n-gram context 是 gap 的主要 driver。若用离线 train 频次表（ngram_global_frequency_v2， 一个"与训练完全解耦的独立统计者"）判定低频区间（hit count 1-200），并在这些 context 上把 n-gram 注入 gate 强制置零， 则低频 context 不再注入 n-gram → gap 应减弱/消除。

实现：新增 env NGRAM_LOWFREQ_GATE_ZERO=1 + NGRAM_GLOBAL_FREQUENCY_CUSTOM_RANGES=bigram:1-200;trigram:1-200； 在模型主 forward 里用 GlobalNgramFrequencyIndex.mask_for_ranges 算出低频位置的 [B,T] 布尔 mask， 在 _add_value_residual 里把该位置的 value_gate 置零（gate=0 → n-gram value 不注入）。 mask 从 epoch 1 起全程生效（不是 step 338 后），目的是"杜绝"低频 context 的 n-gram 注入。 与已有 readout-mask（value 置零）的区别：本实验置零 gate（直接关闭注入通道，且 gate 仍收梯度但被强制为 0）。

  • exp4（per-epoch hash 错位）在统一口径下 final gap 0.282（−79%，验证通过）；exp5（低频 gate 清零 1-200）无效 ——因为 novel（count=0）不在 1-200 范围内，val 翘起主体是 novel；exp7（0 起阈值，含 novel，即 over-encoding 代理）验证失败——低频桶 gap 不降反升、记忆转移给 backbone，见 §12.4。

12.4 exp7（over-encoding 代理）验证失败 + 3-seed 稳健性

  • 3-seed 稳健性（2026-08-04 补跑完成）：p1_reset_all_e2 0.121 / 0.123 / 0.122、p2_readout_mask_e1 0.116 / 0.121 / 0.126——两个 −89% 干预跨 seed 塌缩到 ~0.12（std ≤0.005）；p2_freeze_table_e1 0.559 / 0.656 / 0.564（−50%）、p2_table_gate_only_e1（冻结 reader/backbone）0.507 / 0.580 / 0.374（−59%）同样稳健；p2_gate_freeze_e1 0.865 / 1.234 / 0.838（−19%，弱效应确认）；p1_reset_ref_e1 / p1_reset_rand_e1 0.992/1.391/1.076、1.126/1.051/1.332——小规模行回滚跨 seed 均 null（≈0），排除「回滚操作本身」artifact，历史效应是「全表内容」级的。控制组本身跨 seed 波动大（1.10–1.53，训练动力学敏感）。
  • p2_freeze_both_e1（table+gate 一起冻结）final gap 0.572 ≈ 只冻结 table（0.559）， gate 冻结不叠加 → gate 是次要放大器（与 p2_gate_freeze_e1 −21% 一致）。
  • exp7 结果：低频 gate 清零含 novel（bigram/trigram 0-200 / 0-1000）final gap 1.280 / 1.686， vs 控制 1.096——未消除 gap，反而略增。mask 已确认在 train/eval forward 中正确生效 （作用于 gate 输出，含 novel 的 ranges 已加载）。分桶诊断：被 mask 的低频桶 gap 不降反升 （bigram ≤200：1.40→1.66→2.10），未 mask 的高频桶也升。
  • 机制：gate 是学出来的、输入侧不含频率信息，不是频率干预的有效位点；强制清零低频 gate 后， 固定顺序 replay 下模型把低频 train 位置的记忆转移给 backbone（train 3.38→2.98，val 4.47→4.66）→ gap 维持或扩大。 频率结构存在于表/行内容与 train 数据统计（P1 e2 回滚 −89%、toy gap(r) 单调），不在 gate 里。 BPE/over-encoding 的 gate-zero 代理不成立；「真正 BPE 合并高频组合/低频共享行」由 §16.11 的 token 重映射代理实现（T=8000 → gap −67%、长时程稳健 0.28）。

12.5 对照 svbird 频率遮罩实验（nanoGPT 的 F 部分）

这一节在说什么（人话）

svbird 在 nanoGPT 上做了一组「按频率掐掉 n-gram 注入」的实验，发布在 https://svbird.github.io/ngram-gap-regime-bridge/（F 部分，2026-08-03 已完整）。 它和我们的 P1/P2 是同一类干预、不同位点：我们 §12 干预「表的内容」和「整体注入通道」； svbird 干预的是「某个精确组合的查表输出值」，并按该组合在训练里出现的精确次数分桶 （0 次 / 1–5 次 / 6–200 次 / 1000+ 次）。

口径提醒：svbird 是它自己的 nanoGPT 分支，gap 口径是「最后 100 步的在线 gap」 （同一步的 val loss − raw train loss），且从 step-337 checkpoint 恢复、epoch 2 起生效； 我们的数字是 baseline_current 的 final gap@1000（val 每 50 步采样）。 两边的数值不能直接比，能比的是方向与机制。

13. 合成小实验（toy）：重复越少的组合，忘得越干净

前面的实验用的都是真实文本。这一章我们造了一个完全由我们自己控制的"微型世界"来验证同一个现象， 好处是每个细节都知道答案。详细报告见 docs/toy-dataset-results.md。

13.1 这个实验在做什么（一分钟版）

我们虚构了一个"语言"，规则只有一条：前面 4 个符号决定下一个符号是什么（100% 确定，没有例外）。然后造了 80 万个符号的训练集，其中有 8 档"重复次数"的组合：

只出现 1 次 / 2 次 / 4 次 / 8 次 / 16 次 / 64 次 / 512 次 / 5120 次。

训练方式跟真实实验一样：把训练集反复重播 30 轮。验证集换成"同一规则生成、但大部分是训练里没见过的组合"的新数据。 用 3 个不同随机数起点（seed，保证结果不是碰巧），共做了 15 次实验。

13.2 结果：15 次实验，全部复现同一个现象

观察结果
训练集被"背下来"了训练 loss 一轮一轮阶梯式往下掉，最后接近 0（规则全记住）。
验证集却卡在高位验证 loss 停在 6.5–8.7，不跟着降——这就是我们要的"落差"（gap）。15/15 次实验全部出现。

13.3 一个边界情况：打乱顺序也没用

我们还试了"每轮把文档顺序打乱再训练"（reshuffle），结果落差基本不变（6.87 vs 7.15）。 原因：打乱顺序不改变每个组合的重复次数，只是换了个先后。这说明驱动现象的不是"顺序"，而是"同一段内容被反复看了多少遍"。 这跟真实实验里"两个 epoch 数据混起来训练仍有 gap"是一致的。

判断题 3：BPE 方向，往哪做？

背景：最初设想——把常见组合合并成单个 token（BPE，一种"把高频字母组合打包"的压缩方法），从而让低频组合不再制造噪声。 我们先用一个偷懒的近似试了试（exp7：把低频位置的 n-gram 注入直接掐掉），结果失败：落差没消（1.28/1.69 vs 控制 1.10）。

为什么失败（人话）：门控通道是模型自己学出来的，它根本不知道哪些组合是低频的；把低频的 n-gram 掐掉后，模型改用主干网络照样把训练集背下来，验证集照样不会 → 落差还在。

15.0 svbird F 实验本身：它到底做了什么（人话完整版，2026-08-04）

一句话：把 n-gram 表里「训练中恰好见过 X 次的组合」的查表输出，在第 2 遍训练开始后直接清零， 看 gap 掉多少——用「按出现次数分桶」的方式，把「频率」变成可以一格一格关掉的开关。 这是外部实验（svbird 页面 F 部分）， 本地已用统一框架复现（§15.5，P0）。

为什么要做这个实验

我们的核心怀疑是：gap 来自 n-gram 表把「低频组合」背了下来——训练反复问它 A，验证换一种问法 B， 它就答错。但这个怀疑之前只有观测证据（§9：统计上低频组合的 gap 大）， 观测不等于因果，可能是别的因素在作怪。这个实验把「频率」本身变成干预： 一次只掐掉一个「出现次数桶」（0 次 / 1–5 次 / 6–200 次 / 201–1000 次 / ≥1001 次）， 看哪一桶的开关对 gap 影响最大。掐的位置是查表输出的值（注入前置零）； 表本身、gate、主干网络都照常训练——所以它不是「把表删掉」，而是「堵住这一桶的输出」。

为什么比较是干净的（同源对照）

同一组内所有 run 都从第 337 步（第一遍训练结束）的同一个 checkpoint 恢复： 相同权重、相同优化器状态、相同随机数、相同数据顺序。从第 338 步起，遮罩组只多做一件事—— 把指定频段的查表输出置零。因此「不遮 vs 遮」的差异，只能来自 step 338 之后的这一个干预， 不会被训练过程的其它差异污染。分组上：v4/v5/v6 与 20260803 各自内部同源（可严格配对）； count=0 的 v3 与 20260729 allgram 是更早的独立 run（只能比曲线形状和剂量方向， 不能把不同来源的绝对 gap 当成配对差异）。

两个结论（人话）

  • 低频 readout 直接参与 gap：掐掉 1–5 次的组合，gap 明显降（−26%）；把 count=0 也遮住后再掐 1–5 次，仍有额外下降——说明这不是「没见过」的假象，低频的精确组合 value readout 本身在贡献 gap。
  • 遮高频不是「制造 gap」，而是「两边一起变差」：遮 ≥1001 次的组合，gap 基本不降，但 train 和 val 的绝对 loss 一起抬高（step 338 起 train loss 高 0.29–0.86）——高频组合对预测本来有用，掐掉是性能代价，不是 gap 来源。
  • 两个效应近似可加：先掐低频（gap 缩小）+ 再加掐高频（loss 跃升），两种曲线变化方向可分辨、能叠加——不是同一种变化被算了两遍。

它证明了什么、没证明什么

证明了：这些「低频 readout 值」对 gap 有贡献，频率是 gap 的因果维度（从观测升级为干预）。 没证明：① 遮 readout ≠ 删掉表的记忆（table 行还在继续更新，只是注入被掐）； ② 低频是唯一来源（只证明有贡献，不证明只有它）。

16. 干净证明：只要有「n-gram 表 + 低频 token」就有 gap（2026-08-04）

前面所有实验都在真实文本上做，这一章用一个完全受控的「微型语言」把整条因果链压缩成一次 2×2 实验。 结论一句话：低频 token 是「燃料」，n-gram 表是「引擎」；两者同时存在、固定顺序反复重播，就必然出现 gap； 去掉任何一个，gap 都显著缓解。这是全项目最干净的一张因果图。

16.1 这个实验在做什么（一分钟版）

我们造了一个微型世界：32,768 条「双 token 前缀 → 下一个 token」的规则，每条规则 100% 确定。 训练和验证各是一批按这些规则生成的文本，训练时把训练集反复重播（和真实实验一致）。关键设计：

  • 低频键：约 3 万个前缀在训练里只出现 1/2/4/8 次；训练里它们后面接的 token 和验证集里接的 token 是独立随机抽的——模型一旦把训练接续「背下来」，验证时这些键必然做错。
  • 共享键：其余前缀出现 16 次以上，训练和验证接的是同一个 token——背下来也没错。
  • 2×2 开关：低频键 开/关 × n-gram 表 开/关，各 3 个随机种子，共 12 次实验。

16.6 与真实实验、svbird F 的衔接（结论收敛）

  • 真实数据（§9 / exp6）：5k+ 高频键 gap ≈ 0、罕见键 gap 最大——toy 的「共享键无 gap」与之一致（真实数据里高频键在验证集里的接续几乎不变）。

19. 受控样本量复播：Transformer 与 MLP trunk 对照（2026-08-06）

这一节记录的是同一个 5-gram 项目的 trigram controlled baseline 的样本量重采样与 trunk 对照。 它不是新的频率定义，也不是新的数据语料：先从完整、对齐的 train/val block 流中固定随机抽取样本， 让一个 epoch 恢复到旧实验的 285 个 optimizer steps；然后在完全相同的数据、表、优化器和训练预算下， 比较标准 NanoGPT Transformer trunk 与 position-wise MLP trunk。所有频率统计都只使用完整上游 train epoch 的真实 trigram context count， 不使用 hash bucket occupancy。

19.1 实验到底做了什么

一条主线，两个 trunk。 两个 run 共享同一份随机采样后的 block 流、固定 validation batches、seed=42 和全部 n-gram 参数； 唯一改变的是 n-gram 注入表之后的 backbone：Transformer 保留原始 attention block，MLP 版本将每个 block 换成 position-wise MLP-only block。

  • 任务：真实文本中抽取的 [c0,c1,c2] → next controlled blocks；每个 block 为 [c0,c1,c2,next,SEP]。
  • 样本量：train 为 20,520 行、val 为 288 行；device batch=72，batch tokens=147,456；因此严格为 285 steps/epoch。
  • 训练：2000 steps，约 7 个完整 replay epochs；input-position bigram + trigram VE，unigram/fourgram 关闭，mixed n-gram optimizer，learning rate=0.004，seed=42。
  • 频率口径：从完整上游 train epoch 预先统计 exact trigram frequency，P50=1、P90=4、P99=28、max=77,928；之后的 block 下采样不改变这份 frequency index。
  • 可比性：两组使用完全相同的 train/validation batch hashes；最终频率图只保留两组都有有效 validation loss 的 1,282 个 exact-frequency points。

19.5 这个对照能说明什么，不能说明什么

能说明：在相同 exact-frequency 定义、相同数据流和相同 n-gram 注入表下，去掉 attention、改用 position-wise MLP 后，gap 仍然存在； 因此 gap 不是 attention 才能产生的现象。Transformer 的 gap 更大，同时 train loss 更低，说明更强的 trunk 拟合能力会放大表中低频 context 的 replay-specific 记忆。

不能说明：MLP 已经“完全复现”了 Transformer 的机制。MLP 的绝对 train/val loss 都更高，存在明显欠拟合；所以本实验是存在性/边界验证，不是容量匹配后的机制等价证明。

  • 这仍然是一个 baseline 数据任务的两个 trunk 条件，不应写成两个独立语料实验。
  • 图 19.2 的频率统计来自完整 upstream train epoch；图 19.3 的 gap 来自 step 2000 的 paired exact-frequency probe，113 个只有 train、没有有效 val 的高频点被排除。
  • 下一步如果要把“5-gram context”严格实现为五个 context token，应重新生成 order=5 数据；本节当前的真实 context 是 trigram，不能把项目目录名当成 context order。

19.6 后续的人造转移任务（设计草案，不与本节结果混合）

为了把真实文本中的不确定性与 replay 记忆机制分开，下一步可以生成严格 5-gram context 的人造序列。建议先保留一个最干净的主方案，再用两个数学对照做稳健性验证：

方案转移矩阵结构可解释参数要检验的点
稀疏 Markov + restart每个状态只连接少数候选后继，并以小概率回到全局背景分布out-degree、restart probability、temperature局部稀疏性与长尾频率是否产生同样的 gap。
低秩 + 稀疏扰动P = softmax(UVᵀ/τ + S)，S 只保留少量局部边rank、sparsity、τ、扰动强度共享低维结构与偶然局部边谁主导泛化。
层级社区 block-Markov先采 latent community，再以 community-level transition 和 within-community transition 生成 token社区数、in/out mixing、层级深度可复用的主题结构是否降低低频 context 的不确定性。

这三个方案都能生成概率可控、可重复采样的 next-token 分布；第一阶段建议只跑“稀疏 Markov + restart”，固定矩阵后分别改变训练重复次数和 context frequency，再把另外两种矩阵作为结构稳健性检查。
